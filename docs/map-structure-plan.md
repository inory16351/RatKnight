## 1. 현재 프로젝트와의 차이

| 항목 | 지금 (`web/src/main.js`) | 핸드오프 요구 |
|---|---|---|
| 단위 | 방 8개 한 줄 연결 (`ROOMS`, 방마다 `L`/`R` 출구) | 맵 0~5 (맵 = 방 여러 개 묶음) |
| 잠금 | 출구 `high` = 높이(이단 점프·벽 차기) 잠금 | 경로마다 능력 a~e 잠금 + 진엔딩 맵 스토리 잠금 |
| 능력 | 이단 점프 = 아이템, 내려찍기·충전 돌진·벽 차기 = 레벨 포인트 스킬 노드 | 보스 처치 보상으로 1티어 2개 + 2티어 1개 선택 |
| 방향 | 출구는 모두 양방향 | 0→1·2·3 단방향, 4·5→1·2·3 단방향, 0 복귀 없음 |
| 보스 | 개굴대왕(하수도) · 레일 지네(종착역), 처치 기록 `G.down` | 시작 보스 1 + 초반 맵 1·2·3 각각 스토리 보스/진엔딩 보스 + 4·5 노말 엔딩 보스 |
| 저장 | 메모리만(`G.save`), 새로고침하면 초기화 | 역할 지정·보상·잠금 해제·탐험·엔딩 기록 영구 저장 |
| 탐험 | 체력 조각 1개, 기록 없음 | 맵 1~5 필수 탐험 목표 완료 판정 |

## 2. 구현 단계

1. **진행 상태 모듈** `web/src/progress.js` — 핸드오프 §8 상태 그대로(`ownedAbilities`, `firstEarlyMap`, `trueEndingMap`, `lateRegionEntered` …), `canTravel` · `onEnterMap` · 보상 3종 함수 · 저장/불러오기. 게임 코드와 분리된 순수 함수로 두고 Node 스크립트로 12가지 경로 자동 검증.
2. **방 표에 맵 정보** — 방마다 `map: 0..5`, 출구에 `need: 'a'..'e'`, `oneWay`. `exitOk`에 `canTravel` 연결, 맵 경계를 넘는 출구에서만 검사. 막힌 출구는 능력 색 임시 박스(문)로 표시.
3. **그레이박스 월드** — 맵 0~5를 임시 방으로 배치. 초반 맵 1·2·3은 연결점이 많음(0에서 들어옴, 이웃 2곳 양방향, 4·5로 나감, 4·5에서 돌아옴) → 맵마다 허브 방 + 보스 방 + 탐험 방 구성.
4. **보스 보상 선택 창** — 스킬 노드 창(`hud.js drawSkills`) 방식 재사용, 보스 처치 후 고를 수 있는 능력만 표시. 두 번째 1티어 선택 시 두 번째 맵·진엔딩 맵 확정.
5. **보스 역할 배치** — 초반 맵 보스 방은 그 플레이의 역할(첫 번째/두 번째/진엔딩)에 따라 다른 보스를 세움. 진엔딩 보스는 `trueBossAvailable` 전엔 등장 안 함.
6. **탐험 목표 · 엔딩 판정** — 맵별 목표 목록, `explorationComplete`, 노말 엔딩 플래그, 진엔딩 보스 해금.
7. **디버그 · 검증** — 월드 맵 디버그 창(현재 맵, 보유 능력, 잠긴 경로, 진엔딩 맵), `__game`에 상태 조작 명령, `tools/verify_map.cjs`로 12경로 + 인수 테스트 자동 확인.

## 3. 바로 정할 수 있어서 Claude가 정한 것

- 능력 잠금 검사는 맵 경계 출구에서만. 같은 맵 안 방 이동은 기존 `high` 규칙 유지.
- 상태 모듈은 엔진 독립 순수 JS로 작성 → 유니티 이식 때 그대로 C#으로 옮기기 쉬움.
- 새 비주얼(능력 문, 보상 창, 디버그 맵)은 임시 박스·코드 도형.

## 4. 결정 기록 (2026-10-30 질문 시트)

### 능력
| ID | 색 | 티어 | 능력 | 통과하는 지형 |
|---|---|---|---|---|
| a | 빨강 | 1 | 3연속 대시 — 기본 대시(1회)를 3연속으로 강화, 공중 가능, 대시 구간 통짜 무적 | 가로형 가시밭, 넓은 보스 패턴, 긴 절벽 |
| b | 초록 | 1 | 패링 — 적 공격 패링, 벽·바닥 가시를 패링해 튕겨 오름(할로우 나이트식) | 가시 벽 수직갱, 가시 바닥 |
| c | 하늘 | 1 | 이단 점프 (기존 아이템을 보스 보상으로 이동) | 높은 선반 |
| d | 보라 | 2 | 수직 슈퍼점프 — 지면에서만 | 맵 4 입구의 높은 수직갱 |
| e | 파랑 | 2 | 단거리 벽통과 — 전방 5~7블럭 앞에 빈 공간이 있으면 순간이동 | 맵 5 입구의 두꺼운 벽 |
| — | — | 공용 | 벽 차기 — 첫 번째 초반 맵 보스 처치 시 두 번째 1티어와 함께 자동 지급 | 맵 안 숨은 길·지름길 전용 (맵 사이 잠금에 안 씀) |

- 스킬 노드 시스템 폐지. 레벨업 자동 해금으로 복귀: Lv2 내려찍기 · Lv3 충전 돌진 · Lv4·5 최대 체력 +1. `skills.js`·노드 창 제거.
- 필수 탐험 목표는 모든 조합에서 달성 가능해야 하므로 a~e 중 특정 능력을 요구하지 않음. 기본 동작 + 공용 벽 차기로만 닿는 자리에 배치.

### 월드
- 기존 방 8개는 참고용으로 보존, 맵 0~5는 새로 설계.
- 지형 1블럭 = 48px (기사쥐 키 56px, 한 번 점프 약 152px ≈ 3블럭, 벽통과 5~7블럭 = 240~336px).
- 단방향 표현
  - 0→1·2·3: 지나가면 뒤에서 막히는 셔터.
  - 1·2·3→4·5: d(슈퍼점프 수직갱)·e(벽통과 두꺼운 벽)가 있어야 지나는 지형.
  - 4·5→1·2·3: 능력 없이 내려오는 지형(절벽 낙하·물길 수영 등). **역방향으로는 어떤 능력 조합으로도 못 오르게** 높이·형태 설계(d 슈퍼점프 포함 검토).
- 맵 사이 통로는 연결마다 개별 통로로 둠(구조도의 화살표 하나 = 통로 하나).
- 필수 탐험 목표 = 그 맵의 모든 방 방문 + 수집품 2~3개.
- 보스 9자리(시작 1 · 맵 1·2·3 각 스토리/진엔딩 2 · 맵 4·5): 개굴대왕·레일 지네를 이름·수치만 바꿔 재사용 + 임시 박스 보스.
- 저장 = 브라우저 localStorage 자동 저장, 디버그에 ‘새로 시작’.
- 노말 엔딩 후 = 엔딩 임시 화면 → 마지막 쉼터 복귀, 같은 기록으로 계속.

### 캐릭터 테스트 3차 (보기 · 본 · 타임라인)

- 리깅 방식 = FK (뼈 각도 쌓기). 칼 경로 공격만 칼끝 목표로 팔 각도를 거꾸로 푸는 보조(`reach`).

### 캐릭터 테스트 4차 (편집 범위 · 계층 · 좌우 분리)
- 좌우 분리: 옆 리그 `upperArmF · foreArmF · thighF · shinF`, 정면 리그 `upperArmR · thighR · shinR` 를 같은 그림으로 따로 만듦(`rig.js ALIAS`). 이제 한쪽 팔·다리만 고칠 수 있음.
- 계층(`rig.js HIER`): 부위마다 부모 · 붙는 관절 · 돌리는 자세 값. [리깅] 탭에 트리, 화면에 쐐기 본(뿌리 → 자식 방향), 고른 부위 금색 · 자식 주황 · 부모 줄기 분홍, 자식 축이 관절에서 떨어지면 점선.
- 편집 범위(아래 막대): **전체 리깅** = 리그 덮어쓰기(모든 동작) / **프레임별** = 지금 동작의 고른 프레임에만 키. 프레임별에서 관절 끌기 = 그 부위를 축 둘레로 돌림(FK 자세 키), 엉덩이 = 몸 위치, Alt 끌기 = 이 프레임만 부위 그림 위치(`radj`, 키 사이 보간).
- **자식과 함께 / 개별**: 개별이면 전체 리깅에선 자식 그림이 제자리(자식 축 보정), 프레임별에선 자식이 화면 각도 유지(반대로 돌림).
- 정면 리그의 프레임별 편집은 부위 그림 위치(Alt 방식)만 됨 (정면 자세는 코드가 계산).

### 캐릭터 테스트 5차 (되돌리기 · 동작 길이)
- [프레임] 탭 ‘원래대로 되돌리기’: 이 프레임 리깅 · 이 동작 리깅(자세·부위 위치 키만, 무적 등 상태는 남김) · 전체 리깅(리그 덮어쓰기 옆·정면) · 모든 동작 리깅.
- ‘동작 길이 (프레임 수)’: 공격 = 예비·휘두르기·회복 프레임 수 · 그 밖(패링·대시·슈퍼점프·피격·사망) = 전체 프레임 수(실제 길이가 바뀌고 자세는 같은 비율로 펴짐, 대시는 길어진 만큼 더 멀리) · 패링 = 받아넘김 창 프레임 수. ‘키를 비율대로 옮기기’ 선택 가능. 저장 = `motions[동작].time` (`wind/act/rec` 초 · `scale` · `win` 초). 프레임 번호 기준 = 실제 시간(`fclock`).

## 6. 맵 제작 도구 2판 (2026-10-30, 사용자 지시로 다시 만듦)
- **거대한 맵 한 장**: 48px 칸 격자를 32×32 칸 청크로 저장(`data/world.json` version 2: `tiles` · `area` 청크, `regions`, `rooms`, `objects`, `passages`). 포탈·화살표 연결 없음.
- **지역 = 색 구역**: 같은 격자에 지역 번호를 칠함(할로우 나이트 지도처럼 지역별 색). 지형도 그 칸 지역 색으로 그림. 기본값 = 구조도 배치대로 지역 0~5 를 대강 칠해 둠(자유롭게 다시 칠하기).
- **통로 = 실제 지형**: 지형으로 직접 만들고, ‘통로 표시’ 오브젝트로 구조도의 어느 연결(19개 목록)인지 지정 → 검사에서 빠진 연결 표시.
- **선택 단위만 다름**: [지역] 붓·사각형·고르기 / [방] 카메라 구역 사각형 그리기·옮기기(안의 지형·물건 같이)·크기 / [타일·오브젝트]. 화면은 하나, 휠 확대(멀리 = 지역 이름, 가까이 = 칸 선·가시 모양).
- 예전 1판(지역 상자 + 화살표) 데이터 형식은 버림.
- **타일·리소스 (2026-10-30)**: [타일·오브젝트]에서 ‘타일셋 지역’을 고르면 그 지역의 바닥 1~5 · 가시 1~3(방향 ↑↓←→) · 오브젝트 1~10 · 광원 1~3 · 장식 1~5, 공통으로 발판 · 물 · 용암 · 지우개. 리소스 그림이 나오기 전까지 전부 임시 박스(지역 색, 번호 표시, 광원은 빛 반경 원).
  - 칸 글자: 지역 타일 = U+0100 + 지역×32 + 번호(0~4 바닥, 5~16 가시 n×방향), 공통 `=` 발판 · `~` 물 · `%` 용암.
  - 지역 오브젝트·광원·장식은 오브젝트(`type: prop|light|decor`, `rg`, `n`, w×h). 크기·이름·빛 반경은 ‘리소스 정의’(`world.assets[지역]`)에서 고치면 놓인 것도 같이 바뀜.

### 맵 제작 3판 (2026-10-30, data/world.json version 3)
- **레이어**: `layers` = ‘기본 지형’ + 통로마다 ‘통로 레이어’(`passage`, `zone` 구역, `tiles`). 통로 레이어끼리는 화면에서 겹쳐도 지형이 섞이지 않음. 게임 쪽 약속(그레이박스 때 구현): 플레이어가 통로 구역 안에 있으면 기본 지형 + 그 통로 레이어 지형으로 충돌, 구역 밖이면 기본 지형만. 겹치는 통로 사이 전환은 통로 입구(구역 경계)에서.
- **선택 단위 4개 (드롭다운)**: 지역 · 통로(레이어·구역) · 방 · 타일·오브젝트. 화면은 하나.
- **지역**: 도구 = 붓 · 사각형 · 고르기·범위 조절(테두리 손잡이 8개, 늘어난 빈칸만 칠하고 줄어든 곳은 비움, 지형은 그대로) · 통째로 옮기기(그 지역 칸 + 위의 모든 레이어 지형 + 오브젝트 + 방). 패널에 범위 x·y·w·h 숫자, 5칸씩 옮기기 버튼.
- **통로**: 구조도 19개 목록(● 지형 있음 · ◐ 레이어만 · ○ 없음) → ‘통로 레이어·구역 만들기’(두 지역 가운데에 24×16 기본 구역) → 구역 안쪽 끌기 = 옮기기, 손잡이 = 크기, 빈 곳 끌기 = 새로 그리기 → ‘이 레이어에 지형 그리기’. 능력·방향·표현·메모 수정.
- **타일·오브젝트**: 레이어 고르기, 종류 ‘범위 선택·옮기기’(끌어 범위 → 안쪽 끌기 = 옮김, 화살표 버튼 1칸, Delete = 범위 지우기, 옵션 = 모든 레이어 · 지역 색도 · 오브젝트도). 오브젝트도 레이어에 속함.
- **기본 구조**: 지역 사이 30~40칸 간격(통로 둘 자리).
- **시각화**: 편집 레이어만 또렷·나머지 흐리게, 통로 구역 점선 + `통로 1→4 · d` 이름, 고른 것 손잡이, 옮기는 중 미리보기, 왼쪽 아래 작은 지도(누르면 이동) · 범례(지역 색 · 통로 능력 색 · 편집 레이어), 아래 상태 줄(칸 · 지역 · 방 · 통로 구역 · 레이어 · 선택 범위), 위 ‘지금’ 표시.
- 예전 2판 파일은 불러올 때 3판으로 바꿈(‘통로 표시’ 오브젝트는 버림).

### 캐릭터 테스트 6차 (프레임별 본 길이 · 관절 고르기)
- 관절 고르기 = 겹친 것 중 가장 가까운 관절(고른 부위 우대, 관절과 자식 축이 겹치면 관절 먼저). 예전엔 목록 앞의 것(망토 등)이 잡혀 엉뚱한 부위가 돌았음.
- 프레임별 본 길이: ‘이 프레임만’에서 Shift + 관절 끌기, 또는 [리깅] 탭 ‘이 프레임만 → 본 길이 ×’. 저장 = `radj[부위].len` (키 사이 보간), 붙은 자식이 따라감, 칼끝 궤적에도 반영(`bladeAt` adj).
- 실행: 프로젝트 폴더의 `start_tools.bat` 더블클릭 = 서버가 없으면 최소화 창으로 켜고 캐릭터 테스트 · 맵 제작을 브라우저로 엶.
- 지우개 (2026-10-30): 위 막대 [지우개 (E)] · 타일 종류 ‘지우개’ = 타일(이 레이어) · 타일(모든 레이어) · 오브젝트만 · 타일+오브젝트, 붓 크기 적용. 지역 모드 도구 ‘지우개’ = 지역 색만. 붓·지우개 끌기는 지난 칸~지금 칸을 선으로 이어 빈칸 없음. 불러온 파일은 빠진 값을 채우고(repair), 숨긴 레이어에 칠하면 자동으로 다시 보임.
- 어니언 스킨 (2026-10-30): 아래 막대 ‘어니언 스킨’ = 미리보기에서 이전 프레임 파랑 · 다음 프레임 핑크, 각각 한 장에 그려 40% 로 캐릭터 뒤에 얹음(`main.js drawOnion`). 예전엔 도트화 판 안에 반투명으로 그려 도트화가 지워서 안 보였음.
- 멈춤 방지: 게임 화면 갱신(`frame`)이 오류 한 번에 멈추지 않게 하고 오류는 도구 알림으로. 저장본 적용 중 그림·리그를 못 불러오면 원래 리그로 두고 알림.

### 캐릭터 테스트 7차 (끌기 동작 · 미리보기 안내)
- 아래 막대 ‘끌어서 고치기 → 동작’: 회전 · 이동 · 본 길이 · 파츠 크기(본 + 그림). 범위(전체 리깅 / 이 프레임만) 둘 다에서 네 가지 모두. Shift = 본 길이, Alt = 이동으로 잠깐 바꿈.
  - 전체 리깅: 회전 = 축 둘레로 관절(자식 자리)과 그림을 돌림(‘개별’이면 그림만), 본 길이 = 관절을 축에서 늘림, 파츠 크기 = 관절 + 그림 배율, 이동 = 예전처럼 관절·축 좌표. 저장 = 리그 덮어쓰기 `joints` · `adj`.
  - 이 프레임만: 회전 = 자세 키, 이동 = `radj.dx/dy`, 본 길이 = `radj.len`, 파츠 크기 = `radj.len` + `radj.sc`.
  - [리깅] 탭 숫자: 전체 ‘본 길이 × (그림도 같이 = 파츠 크기)’, 이 프레임 ‘본 길이 ×’ · ‘파츠 크기 ×’.
- 미리보기(게임 멈춤) 중 조작 키를 누르면 바로 실제 조작으로. ‘전부 기본값으로’ 뒤에도 실제 조작으로 돌아감. 배지에 ‘미리보기 · 게임 멈춤’ 표시. (프레임 편집 뒤 캐릭터가 안 움직이던 건 미리보기 상태가 남아 있던 것)
